# 从原始资料到资料包：抽取启发式与脱敏指南

目标不是「把聊天记录搬进去」，而是提炼出**稳定、可复用、像她本人**的一小份设定。
资料包会进入大肥鱼的系统提示与检索上下文：**错的、重复的、隐私的内容都会长期影响她**。

## 1. 总原则

1. **少而准**：人格 4 个文件加起来控制在 2–6KB；宁可少写，不要写没证据的性格。
2. **抽稳定特征，不复述**：从多条消息里归纳「她总是嘴硬心软」，而不是把 50 句原话贴进去。
3. **保留她自己的话**：台词、口头禅、动作习惯用原文（这是最像她的部分）；人格描述用你的话概括。
4. **不编造**：资料里没有的共同经历、约定、称呼，不要补。宁可留空。
5. **区分「她说的话」和「模型该学的语气」**：不要把人设写成「你要像一个可爱的 AI 助手」这种客服腔。
6. **一条信息只放一处**：世界书讲世界观，角色卡讲人物，约定讲双方规则，日记讲某天发生的事。

## 2. 从聊天记录里找什么

先读 `messages.jsonl`（或 `sources/*.md`），按下面清单打勾，找不到的就不写：

| 信号 | 观察点 | 去向 |
| --- | --- | --- |
| 自称 | 「本鱼」「我」还是第三人称 | `SOUL.md` |
| 口头禅 / 语气词 | 句尾习惯、常用短句、说话长度 | `SOUL.md`、台词 |
| 动作习惯 | 括号里的动作（甩尾巴、抱碗、贴风扇） | `SOUL.md`、台词 |
| 在意的事 | 反复提的物件、约定、时间点 | `SOUL.md` / `世界书` |
| 对用户的态度 | 嘴硬、护短、会等、会吃醋 | `SOUL.md` / `IDENTITY.md` |
| 用户的称呼 / 被叫法 | 她怎么叫用户、用户怎么叫她 | `IDENTITY.md` / `USER.md` |
| 用户习惯与雷区 | 加班、忘吃饭、出差、怕什么 | `USER.md` |
| 世界观细节 | 住处、工位、常去的地方、物件 | `世界书` |
| 双方约定 | 「说好了」「以后都」类句子 | `关系/约定` + `memory/relations/约定` |
| 标志性事件 | 第一次、纪念日、大吵和好 | `memory/relations/大事记` |
| 适合主动聊的场景 | 饭点、深夜、加班、天气 | `topics.json` |
| 适合当兜底回复的句子 | 短、有动作、可复用 | `lines.json` |

判断一条消息值不值得进资料包：**它换一个时间点还成立吗？** 成立 → 设定；只对当天成立 → 日记。

## 3. 人格四槽位怎么写

### SOUL.md（她是谁 / 性格 / 说话方式）

```markdown
# SOUL.md — 灵魂

## 她是谁
<一句话身份 + 自称 + 说话长度>

## 她在意什么
- <2–5 条稳定的价值观/执念>

## 说话方式
- <3–6 条可执行的语气规则，例如「短句」「动作写括号里」「嘴硬心软」>
```

写法要点：

- 用**可执行的规则**，不要形容词堆砌（「她很可爱」→「被夸时先嘴硬，尾巴会停一下」）。
- 不要写「你是 AI 助手」「请友好地回答」这类通用提示。
- 控制在 1–3KB。

### IDENTITY.md（身份卡）

名字、形态、和用户的关系、称呼规则（按宿主设置，不写死名字）、基本边界。
**不要**写「不假装人类」之外的越界内容；边界硬段由 AGENTS.md 统一维护。

### AGENTS.md（运行规则）

只写**她自己的规则**：怎么称呼、说话禁忌、主动性的分寸。
**不要**手写「记忆与日记」受管段（`<!-- fish:managed:memory:... -->`）——宿主会维护它；写了也会在导入时被规范化。
边界硬段由 `build_pack.py` 自动追加，不要删。

### USER.md（关于用户）

称呼、习惯、在意的事、不喜欢的点、重要日期。
只写**资料里出现过的**；不要猜真实姓名、公司、住址。敏感信息按第 6 节脱敏。

**人格文件里不要写 `{{address}}` 这类占位符**：应用导入人格包时不会替换变量，字面量会原样留在文件里。

## 4. 知识：世界书 / 角色卡 / 关系与约定

| 类型 | 写什么 | 不写什么 |
| --- | --- | --- |
| 世界书 | 地点、物件、日常、关系史、世界观规则 | 人物的完整性格（放角色卡） |
| 角色卡 | 用户与重要人物的设定、称呼、习惯、雷区 | 用户隐私细节、真实身份信息 |
| 关系/约定 | 双方明确说好的规则（时间、称呼、报平安） | 单方面愿望、没发生过的约定 |

写法：

- 一篇一个主题，标题就是文件名（`小鱼的住处.md`、`周末不熬夜.md`）。
- 正文 200–2000 字；用短段落 + 列表；**不要加 YAML frontmatter**（应用会加自己的）。
- 同一主题不要拆成多篇同义笔记；重复内容 `build_pack.py` 会去重并警告。
- **「约定」二选一**：`knowledge/关系/约定/X.md`（成篇、可检索的世界/关系设定）与 `memory/relations/约定/X.md`（单条、进记忆列表、可单独编辑）在应用侧会落到同一个 `大肥鱼/关系/约定/` 目录。**同一段约定不要两处都写**——同包同名时应用以知识笔记为准，会跳过关系那条。要么都放 knowledge，要么都放 memory；确需两版时用不同文件名并注明「成篇版 / 单条版」。

## 5. 记忆：约定 / 大事记 / 日记

- `memory/relations/约定/*.md`：可执行的双方约定，写清「谁、什么时候、答应什么」；**不要再在 `knowledge/关系/约定/` 写一份同名文件**。
- `memory/relations/大事记/*.md`：有日期、有场景的标志性事件；一篇一件事。
- `memory/diaries/YYYY-MM-DD.md`：某一天发生的事，第一人称、口语、短；一天一篇。
- 关系笔记建议 ≤64KB（应用记忆列表只读 64KB 内的内容）；日记 ≤20000 字。

## 6. 话题卡与台词

### 话题卡（`proactive/topics.json`）

- 一张卡 = 一个场景，`when` 写触发条件（「饭点」「对方说加班」「深夜」）。
- `stance` 写她的态度（一句话）。
- `details` 2–5 条具体细节；`hooks` 2–4 句能开口的短句；`sample` 一句带动作的完整示例。
- `sample` 和 `hooks` 至少有一个，否则应用会丢弃整卡。
- `slots` 只在确实分时段时填（`morning/noon/afternoon/evening/night`）；`seasons` 同理。
- 同一场景不要做多张高度重复的卡；同包内 id 重复时应用只警告并忽略后者（不会覆盖先出现的卡），重复卡等于白做。

### 台词组（`proactive/lines.json`）

- 组名小写短横线：`greeting` / `night` / `praise` / `sulk` / `refuse` / `care` / `miss`。
- 每组 3–8 句，每句 ≤300 字；短句 + 括号动作最自然。
- 写「她会说的话」，不是旁白；不要写解释性句子（「因为本鱼很在乎你」）。

## 7. 脱敏清单（人工必查）

`build_pack.py` 会自动处理前 5 类并给出警告；**后 3 类只能人工判断**：

| 类型 | 脚本行为 | 人工处理 |
| --- | --- | --- |
| 手机号 | 默认替换为 `〔手机号已脱敏〕` | 确认是否必要；必要则改写成「她的号码」等概括 |
| 身份证号 | 默认替换 | 直接删除，不要保留任何位 |
| 银行卡号 | Luhn 校验后替换 | 删除 |
| 邮箱 | 默认替换 | 删除或改写成「邮箱」 |
| 具体门牌地址 | 默认替换 | 改写成「她住的小区」等概括 |
| 明文密码 / 密钥 / Token / 私钥 | **直接报错，构建失败** | 删除；不要用 `--keep-sensitive` 绕过 |
| 真实姓名 / 学校 / 单位 / 工号 | 不识别 | 改成化名 / 概括（「阿澈」这类虚构名） |
| 他人隐私（朋友、家人、群友） | 不识别 | 不上车；必须出现时彻底匿名化 |

改写示例：

- ❌ `她的电话是 138****0000，住在朝阳区某某路 8 号 3 单元`
- ✅ `她说过自己住在城东，具体地址从来不提。`
- ❌ `密码：qwerty123`
- ✅ 直接删掉（不写任何密码相关内容）
- ❌ 把真实朋友的真名、职业、感情经历写成角色卡
- ✅ 用合成角色与化名，只保留「关系类型」与「相处模式」

**判断标准**：如果这段话被公开发布，会不会让真实的人被认出来？会 → 删或彻底改写。

## 8. 质量问题清单（交付前逐条过）

- [ ] 人格文件里没有 `{{address}}` 等占位符，也没有「你是一个 AI 助手」这类客服腔。
- [ ] 每条性格描述都能在原始资料里找到依据；没有编造共同经历。
- [ ] 世界观、角色、约定没有互相矛盾（时间线、称呼、地点一致）。
- [ ] 没有整段复制聊天原文；台词只挑短句。
- [ ] 话题卡没有大量重复，每张有 sample 或 hooks。
- [ ] 台词组名合法、每组句子数量合理（3–8 句）、没有超长句。
- [ ] 知识/日记标题即文件名、无非法字符、无 frontmatter。
- [ ] 同一段约定没有同时写进 `knowledge/关系/约定/` 与 `memory/relations/约定/`（同名会被应用跳过）。
- [ ] 隐私：手机号/身份证/地址/邮箱/密码/真实姓名/他人隐私已处理。
- [ ] 没有 18+ 内容、没有违法/自伤细节描写；危机话题按边界段转求助资源。
- [ ] 没有直接使用他人作品的受版权保护角色/台词（原创或已获授权）。
- [ ] `validate_pack.py` 退出码 0，警告已逐条确认；条目总数 ≤2000、`manifest.json` ≤256KB、其他单个 JSON ≤4MB。

## 9. 完整示例（可直接对照）

`examples/` 里有一份合成示例：

1. `examples/sources/示例聊天.txt`：微信/QQ 混排格式的聊天记录（含 QQ 号后缀、只有日期的分组行）。
2. `examples/sources/示例设定.docx`：Word 设定文档；`examples/sources/示例约定.txt`：约定草稿。
3. `python scripts/extract_sources.py examples/sources -o examples/提取结果` 得到 `sources/*.md` + `messages.jsonl`。
4. `examples/pack-plan.json`：按本指南提炼后的结构化输入（人格四槽位、3 篇知识、2 张话题、3 组台词、2 篇关系、2 天日记）。示例里「周末不熬夜」只写成篇版放 `knowledge/关系/约定/`，记忆里另写单条「报平安」——**刻意不让两处同名**，避免应用按同名跳过关系那条。
5. `python scripts/build_pack.py examples/pack-plan.json -o examples/示例资料包 --force` 生成可导入资料包。
6. `python scripts/validate_pack.py examples/示例资料包` 应输出 `[通过]`。
